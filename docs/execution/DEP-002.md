## Boundary

The rehearsal used a unique LocalDB instance and database only:

- instance: `GTASVPP_RECOVERY_000000DFE25F`
- database: `GTAS_VPP_RECOVERY_000000DFE25F`
- marker: `GTAS_LOCAL_RECOVERY_PROOF`

It did not target `MSSQLLocalDB`, `MSSQLSERVER`, a shared database, DigitalOcean,
production, or any credential/provider environment.

## Evidence

1. Created and started the unique LocalDB instance.
2. Created the disposable database and inserted one deterministic marker row.
3. Ran `BACKUP DATABASE ... WITH INIT, CHECKSUM` followed by
   `RESTORE VERIFYONLY ... WITH CHECKSUM` successfully.
4. Backup artifact was 3,330,048 bytes with SHA-256
   `4D6798A03A5B02EF2A415A93E78D80EB7E65BF285EB1EB572D2F94A442C4F23D`.
5. Dropped the database, restored it from the backup with `REPLACE, RECOVERY`,
   and queried the marker successfully: `1 GTAS_LOCAL_RECOVERY_PROOF`.
6. Ran a second `RESTORE VERIFYONLY ... WITH CHECKSUM` successfully after the
   restore.
7. Dropped the restored database, stopped/deleted the unique LocalDB instance,
   and removed the temporary backup artifact. Cleanup completed with no
   persistent database or backup left behind.

## Acceptance and residual boundary

This proves the approved local-only backup/restore alternative and is not a
production deployment claim. The deployed/server paired backup, off-host copy,
health probe, and production restore remain owner-controlled evidence for a
future server release; the guarded `deploy/backup-db*.sh` and
`deploy/restore-db*.sh` scripts were also syntax/guard checked separately.
