## Why this correction was required

A production screenshot proved that the earlier `DONE` reconciliation was too
optimistic. `LoginPage` still sent the raw HTTP response body to a Radzen toast,
used the hard-coded English title `Login failed`, and the toast stylesheet did
not bound the Radzen container. The result violated the existing requirements
for Vietnamese-first UI, safe error text, no raw details and responsive
notification presentation.

## Delivered

- Login failures now map HTTP status to paired Vietnamese/English resources;
  raw JSON, HTML and transport details are never rendered.
- Timeout, connection and malformed-success responses use safe localized
  fallback messages.
- Transient feedback is a compact top-right card (maximum 400 px), uses the
  repository tokens, supports reduced motion and becomes viewport-bounded on
  mobile. The old glassmorphic/full-width treatment was removed.
- The durable header inbox remains separate from transient toast feedback and
  now has loading failure, stale-data and retry states. Refresh failures no
  longer break the Blazor circuit or discard already loaded notifications.
- Added unit coverage for login failure mapping and an isolated Playwright test
  that checks localized text, raw-detail redaction, width, position and page
  overflow at all three required viewports.
