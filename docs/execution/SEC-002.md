## Objective

Make database startup deterministic and safe:

1. schema migration and neutral reference bootstrap are separate from the
   optional demo fixture;
2. production/live bootstrap never creates demo or business users;
3. missing, corrupt, or failed required SQL aborts the process and never writes
   that profile's success marker;
4. a `TestEnv`-labelled demo profile is explicit, guarded, and idempotent;
   executed evidence uses a uniquely named disposable LocalDB target.

## Why now

The previous `MigrateAndSeed` startup path mixed schema, authorization metadata,
catalog data, company data, and account fixtures. Required SQL errors could be
logged and swallowed, leaving a partially initialized database that looked
successful. This is a release-containment task before authentication,
environment binding, or deployment work can be trusted.

## Deviations from plan

- The first implementation isolated legacy demo accounts into a new SQL file.
  Security review rejected that design because it still committed test
  accounts, e-mail/PII-like values, a shared password verifier, and collision-
  prone numeric user IDs. Final design removes account provisioning and P04
  mapping from database bootstrap entirely.
- `MigrateAndDemo` now reconciles its idempotent fixture on every explicit run
  rather than trusting a marker-only shortcut; this prevents a stale marker
  from suppressing the seed steps. The department fixture now inserts each
  missing stable code independently and no longer contains duplicate
  `SOURCING` source rows.
- No new automated SQL integration framework was added because that belongs to
  QA-001. Executed LocalDB evidence is recorded without claiming Docker/
  cross-platform coverage.

### Safe local demo invocation boundary

There is intentionally no command that points at the checked-in Development
connection (`MKGAME/GTAS_VPP_TEST`). Create a unique disposable LocalDB target,
use existing ignored local secrets, set the following only for that process,
and restore the process environment afterward:

```powershell
$keys = @(
  'ASPNETCORE_ENVIRONMENT', 'DISABLE_DOCKER_DB_OVERRIDE',
  'DatabaseInitialization__Mode', 'DatabaseInitialization__RunOnly',
  'DatabaseInitialization__AllowDemoData',
  'DatabaseInitialization__Environments__0', 'ConnectionStrings__TestEnv'
)
$previous = @{}
foreach ($key in $keys) {
  $previous[$key] = [Environment]::GetEnvironmentVariable($key, 'Process')
}
try {
  $env:ASPNETCORE_ENVIRONMENT = 'Development'
  $env:DISABLE_DOCKER_DB_OVERRIDE = 'true'
  $env:DatabaseInitialization__Mode = 'MigrateAndDemo'
  $env:DatabaseInitialization__RunOnly = 'true'
  $env:DatabaseInitialization__AllowDemoData = 'true'
  $env:DatabaseInitialization__Environments__0 = 'TestEnv'
  $env:ConnectionStrings__TestEnv = '<unique disposable TestEnv connection string>'
  dotnet run --project gtas_vpp_be/gtas_vpp_be/gtas_vpp_be.csproj --no-launch-profile
}
finally {
  foreach ($key in $keys) {
    [Environment]::SetEnvironmentVariable($key, $previous[$key], 'Process')
  }
}
```
